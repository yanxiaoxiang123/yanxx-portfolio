## 背景

我想验证一件事：把大模型放进一条真实的投研流程里，它能不能不只是聊天，而是有边界地调用工具、留下可检查的记录，最后接上人的判断。Backing 是这个想法的实验场，也是我用来练习完整系统开发的个人项目。

## 我做了什么

平台把「行情接入 → 技术选股 → 策略回测 → 多 Agent 研究 → 人工审批 → 模拟下单」串成一条链路。我独立完成了需求取舍、后端与前端实现、部署和日常维护。

- 用 LangGraph 编排数据质检、技术研究、策略、回测审查和风险控制节点，支持多轮上下文、流式推理、工具调用、最大步数约束与超时取消。
- 持久化 Run、Step、Tool Call、Artifact 和 Approval 等执行事实，通过 SSE 推送进度，并支持断线重放和任务恢复。
- 实现 17 类量化工具的调用网关，用工具白名单、权限校验、Pydantic 参数验证、输出大小限制和调用审计约束模型行为。
- 统一 13 类量化策略的信号与回测框架，计算收益率、年化收益、夏普比率、最大回撤和胜率，模拟盘适配 A 股 T+1、涨跌停、整手和交易费用规则。
- 用 systemd 做每日备份，维护问题修复与验证记录，累计 534 项测试通过。

## 一个取舍

让 Agent 自由调用工具很诱人，但回测最怕两件事：前视偏差，和模型编造一个好看的结果。所以工具网关把时间截断、参数校验和调用审计放在模型之外。模型只能提出调用，不能绕过规则；用 `as_of` 截断行情和事件数据，保证研究只看见当时能看见的信息。

## 结果

系统可以完整跑通从数据到研究结论的链路，中断后能继续，审批环节保留了人的位置。它现在是一个持续维护的个人项目，也是我理解 Agent 系统边界的主要方式。

## 局限

模拟盘不是实盘，不构成投资建议，也没有对外服务的收益或用户数据。534 项测试与功能范围来自项目记录，本页没有独立复跑；公开 README 与开发记录的口径可能不完全一致。
